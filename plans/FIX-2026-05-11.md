**Problem:** When adding a household member, phone number field accepts strings and has no length validation.

**Files likely involved:**

### ISSUE-6: Guard/Resident Login Role Separation [CRITICAL]
**Problem:** 
1. Phone number validated at OTP stage instead of login stage
2. No role separation — entering guard phone in resident login proceeds to OTP
3. Should fail fast: if phone doesn't exist in the correct role's table, reject at login

**Fix Required:**
- Backend `/auth/login`:
  - Accept `role` parameter (RESIDENT, GUARD, ADMIN)
  - Validate phone exists for that specific role BEFORE sending OTP
  - Return 404 "Phone not registered as [role]" if mismatch
- Backend `/auth/send-otp`:
  - Same role-aware validation
- Mobile: 
  - Resident app sends role=RESIDENT
  - Guard app/mode sends role=GUARD
- Clear error messages shown to user on role mismatch

**Files likely involved:**
- `backend/src/auth/auth.controller.ts`
- `backend/src/auth/auth.service.ts`
- `backend/src/auth/dto/login.dto.ts`
- `mobile/lib/features/auth/`
